# AlphaAutomationSolution - Repository Checklist

This checklist was generated by scanning the repository to list required external tools, runtime prerequisites, and exact configuration keys used by the code.

Use this checklist when preparing a machine (local or CI runner) to build and run tests from this repository.

1) Essential runtime & tooling

- .NET 8 SDK (required to build/run the projects)
  - Install: https://dotnet.microsoft.com/download
- Visual Studio 2022/2026 or VS Code with C# extension (recommended for development)

2) UI automation prerequisites

- Chrome browser (required for Selenium web tests)
  - Ensure Chrome is installed and updated to a version compatible with the ChromeDriver package used by the project.
- ChromeDriver
  - The project references the Selenium.WebDriver.ChromeDriver NuGet package (version pinned in AlphaAutomation.csproj).
  - NuGet will copy ChromeDriver into the test output; still ensure local Chrome version is compatible with the driver.
- WinAppDriver (for desktop / Outlook automation)
  - Default expected path (also in appsettings.json and RunConfig.cs):
	C:\Program Files (x86)\Windows Application Driver\WinAppDriver.exe
  - Download: https://github.com/microsoft/WinAppDriver/releases
  - Start it before running desktop/Outlook tests. Default listening URL used in code: http://127.0.0.1:4723
- Microsoft Outlook (if running Outlook automation)
  - Outlook must be installed and configured with the test account used by the automation.

3) NuGet packages that imply runtime behavior

- Selenium.WebDriver (3.141.0)
- Selenium.Support (3.141.0)
- Appium.WebDriver (4.3.2) — used to drive WinAppDriver sessions
- Selenium.WebDriver.ChromeDriver (150.0.7871.4600) — driver binary packaged by NuGet
- ExtentReports (4.1.0) — HTML reporting

4) Ports and services

- WinAppDriver default port: 4723 (http://127.0.0.1:4723) — ensure firewall allows local access and the service is running.

Notes & mapping issues:
- appsettings.json contains a nested "Recipients" object (Recipients.To and Recipients.Cc). RunConfig expects a top-level "To" property. When deserializing the JSON into RunConfig, the nested Recipients object will not populate RunConfig.To. To override recipient in config, either add a top-level "To" property in appsettings.json or modify RunConfig/JSON structure accordingly.

7) Test behavior & toggles

- SendEmail (boolean): if true, tests will click Send in Outlook when composing emails. Default in RunConfig is false; appsettings.json in repo sets it to true — update as needed.
- TimeoutSeconds: used for driver waits and attaching to windows — tune if tests are flaky in slower environments.

9) Recommended machine setup checklist

On any machine where you will run the UI tests (local dev machine or dedicated test VM):

1. Install .NET 8 SDK
2. Install Visual Studio or VS Code
3. Install Chrome browser
4. Ensure ChromeDriver provided by NuGet is compatible with installed Chrome. Update either Chrome or the ChromeDriver package if necessary.
5. Install WinAppDriver to the path configured in appsettings.json or adjust appsettings.json/RunConfig to point to the installed path
6. Install and configure Outlook (if running Outlook tests)
7. Start WinAppDriver.exe prior to test runs
8. Ensure firewall/local policies do not block WinAppDriver (port 4723)
9. Confirm appsettings.json values are correct for the environment (BaseUrl, recipients, SendEmail, timeouts)

10) CI considerations

- Running UI tests in CI requires Windows runners with desktop access (WinAppDriver and Outlook typically need an interactive desktop session). Consider running these tests on self-hosted Windows agents.
- Alternatively, split fast non-UI tests to run in cloud CI and run UI tests on dedicated VMs.
